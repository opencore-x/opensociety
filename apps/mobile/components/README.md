# Mobile components

The mobile theme uses warm neutral surfaces, forest green actions, native system type, and consistent outline icons. Keep screens quiet and useful, with no ad slots, sponsored content, or invented activity. The current palette lives in `../global.css`; native navigation and SVG colors in `../lib/theme.ts` must match it. The app currently uses a light appearance.

Use `ui/Screen` for scrolling forms, `ScreenFrame` for lists containing inputs, and `PageIntro` for screen headings. Keep controls at least 44 points tall, let labels wrap, and preserve system text scaling. `Button`, `Chip`, and `Input` share the same interaction styling. `AdaptiveRow` stacks content on compact screens and at larger text sizes; avoid `flex-1` on its variable-height child views. Use `Section`, `Field`, and `ApartmentPicker` for forms, and `EmptyState`, `ScreenState`, `LoadingState`, and `Feedback` for readable state transitions. Put new copy in both mobile dictionaries in `@opensociety/shared`.

Check native rendering on iPhone and Android. Browser rendering and TypeScript checks do not establish visual acceptance. In NativeWind v5, explicit `contentContainerStyle` is needed for FlatList spacing here, and physical padding properties keep Android TextInput text inset correctly. Give `SafeAreaView` explicit native sizing and background styles, including inside modals. `ScreenFrame` measures its position below the navigation header for Android keyboard avoidance; iOS uses automatic scroll insets. Large text, long labels, keyboard access, and bottom safe areas need a device check whenever layouts change.

The house mark in `../assets/mark.svg` supplies the app icon, adaptive and monochrome icons, splash, favicon, and notification silhouette. From `apps/mobile`, run `node scripts/brand-assets.cjs` after changing it. The generator uses the image tooling already pinned by Expo; generated PNGs are committed with the source. Native asset changes require a new native build.

The 2026-10-03 simulator review covered resident and guard screens on iPhone 17 Pro (iOS 26.5) and Android API 36.1, including 320-point Android width, 1.5x Android text, iOS accessibility-medium text, English/Hindi, keyboard fields, long names, loading/empty/error states, offline feedback, camera permission denial, and fixture-backed form actions. Android's native accessibility tree confirmed named actions, selected rating state, and 48-point rating targets. This does not replace physical-device acceptance or listening through VoiceOver and TalkBack. Lucidity task #101 retains those release checks. Additional regional languages are deferred. Local visual fixtures and screenshots belong in `.context/`; they must not become production data or routes.
